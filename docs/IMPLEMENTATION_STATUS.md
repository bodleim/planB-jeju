# 구현 현황

## 현재 목표

서버 렌더링 기반 일정 화면을 문서 새로고침 없이 전환되는 웹앱형 내비게이션으로 개선 완료.

## 완료된 작업

- 빈 `at` 쿼리는 제주 현재 시각으로 해석하도록 변경했다.
- `cause` 쿼리를 허용 목록으로 검증하고, 잘못된 값은 `ferry_cancelled`로 폴백하도록 변경했다.
- 필터의 위험 병합도 잘못된 원인 값에 방어적으로 동작하도록 보강했다.
- `near=1` 요청에서 이동시간 점수를 추가 반영하도록 계획 생성 경로를 연결했다.
- `CLAUDE.md` 구현 현황을 위 동작에 맞게 갱신했다.
- 내부 링크와 GET 폼 제출을 App Router 클라이언트 전환으로 처리하는 `AppNavigation`을 추가했다.
- URL 쿼리 기반 상태·공유 URL·뒤로가기는 유지하고, 새 탭·수정자 키 클릭·외부 링크는 브라우저 기본 동작을 유지한다.

## 다음 작업

## 알려진 문제 및 장애 요소

- 차량 없는 사용자의 이동시간은 버스 시간표가 아닌 거리 기반 추정이다.
- 기상특보 API는 응답 거부로 판정에 포함되지 않는다.

## 테스트 및 검증

- `npm run lint` 통과 — `AppNavigation` 포함 ESLint 검사 완료.
- `npm run check:filter` 통과 — 잘못된 원인 값이 위험 병합에서 예외를 내지 않는 검증 포함.
- `npm run check:plan` 통과 — 가까운 곳 우선 계획의 총 이동시간이 같은 조건의 기본 계획보다 늘지 않는 검증 포함.
- `npm run build` 통과 — App Router 클라이언트 내비게이션 변경을 포함한 프로덕션 컴파일·TypeScript 검사 완료.
