# 플랜B 제주

> 우도 배가 끊기거나 비 때문에 일정이 망가졌을 때, **지금 있는 곳 주변에서 남은 시간에 맞는
> 일정을 30초 만에 다시 짜주고**, 마음에 안 드는 곳은 스와이프 한 번으로 바꿀 수 있는 서비스.

2026 제주 지역대학 연합 창업 캠프 출품작 — 팀 **우리 친해요** (현용빈, 박범준, 오채원).

여행 **전 추천**이 아니라 여행 **중 복구**입니다. 장소 추천 서비스가 아니라
**일정 재구성 서비스**라는 점이 모든 설계 판단의 기준입니다.

## 무엇이 되나

| | |
|---|---|
| **일정 생성 (F1)** | 현재 위치·남은 시간·여행 성격(동반 1 + 활동 여러 개)을 넣으면 시간대별 계획이 나온다. 모든 방문지는 **도착 시각에 실제로 열려 있다** |
| **시간대 교체 (F2)** | 카드 스와이프(또는 탭 → 대안 시트)로 그 시간대만 바꾼다. 교체 결과도 같은 제약을 다시 통과한다 |
| **후보 필터 (F3)** | 기상·결항·환승·영업·거리 5가지 하드 제약으로 후보를 거른다. **일정을 깨뜨린 것과 같은 위험을 가진 후보는 제외** — 강풍 결항인데 다른 해상 일정을 추천하지 않는다. 제외된 후보는 이유와 함께 화면에 보여준다 |
| **직접 말하기** | "애 둘이랑 갈 만한 실내로 채워줘", "해산물은 못 먹어" 같은 자유 문장을 Gemini 가 구조화된 입력으로 바꾸고, **우리가 준 후보 목록에서 id 만 고른다**. 못 먹는 곳은 제외, 좋아하는 곳은 우선 편성. LLM 이 죽으면 키워드 표로 폴백 |
| **동선 지도** | 카카오맵 위에 출발지→방문지 순서와 동선 표시. SDK 로드 실패 시 SVG 개략도로 폴백 |

## 빠른 시작

```bash
npm install
cp .env.example .env.local   # 아래 키 채우기
npm run dev                  # http://localhost:3000
```

| 키 | 필수 | 용도 |
|---|---|---|
| `DATA_GO_KR_KEY` | ✅ | 기상청 단기예보 (유일한 런타임 실시간 호출). **Decoding 키**를 넣을 것 |
| `NEXT_PUBLIC_KAKAO_JS_KEY` | 선택 | 카카오맵. 카카오 콘솔에서 **JavaScript 키의 [JavaScript SDK 도메인]** 에 도메인 등록 필요 (없으면 SVG 개략도) |
| `GEMINI_API_KEY` | 선택 | 직접 말하기 자유 문장 해석 (없으면 키워드 폴백). [aistudio.google.com/apikey](https://aistudio.google.com/apikey) 무료 발급 |

발표 리허설 URL (한 줄로 시연 흐름 전체가 재현됩니다):

```
/?go=1&cause=ferry_cancelled&from=성산항&remaining=300&party=2&car=yes&at=10:00&companion=couple&activity=indoor&checkin=16:00
```

## 검증

테스트 러너 없이 `node --experimental-strip-types` 기반의 체크 스크립트를 씁니다.
전부 API 키 없이 돕니다.

```bash
npm run build          # 타입체크 포함
npm run check:weather  # 기상청 발표시각·파싱·위험판정
npm run check:places   # TourAPI 운영시간·휴무 파서 + 스냅샷 적재
npm run check:filter   # F3 제약 + F3→F1 불변식 (도착 시각에 열려 있는가)
npm run check:plan     # F1 계획 + F2 교체/재생성 + 발표 시나리오 재현
npm run check:prompt   # 직접 말하기 키워드 폴백
npm run check:intent   # LLM 응답 검증 (목록 밖 id·이상값 차단)
npm run check:api      # 전체 API 키 발급/연결 점검 (python, stdlib only)
```

## 데이터 전략

**API 장애로 시연이 죽지 않는 것이 최우선**입니다. 실패하는 모든 경로에 폴백이 있고,
폴백 사실은 숨기지 않고 화면에 표시합니다.

| 데이터 | 방식 | 비고 |
|---|---|---|
| 기상청 단기예보 | **실시간 호출** | 실패 시 중단 원인만으로 위험 판정 + '확인 필요' 표시 |
| 한국관광공사 TourAPI | **사전 수집 → JSON 커밋** (`npm run snapshot`) | 성산항 반경 15km, 103곳 수집 → 운영정보 확인된 72곳만 자동 편성. 수집 시각을 화면에 표시 |
| 여객선 결항 | **사용자 입력** | 안정적 공개 API 없음. 배로만 가는 곳은 자동 편성에서 제외 |
| 이동시간 | 거리 기반 **추정** | 제주 ITS 승인 대기. 차량 없음일 때 대중교통 시간도 추정이며 화면에 그렇게 밝힘 |

## 설계 원칙 (어기면 안 되는 것)

1. **LLM 은 사실을 생성하지 않는다.** 운영시간·결항·휴무는 공공데이터에서만 온다.
   LLM 은 문장 해석과 '검증된 후보 중 고르기'만 하고, 고른 곳도 제약 검사를 통과해야 편성된다.
2. **하드 제약이 점수보다 우선.** 문 닫은 곳이 결과에 뜨면 시연이 무너진다.
3. **같은 위험의 후보 제거.** 우천으로 오름이 취소됐는데 다른 야외 코스를 넣지 않는다.
4. **출처·기준시각 표시.** 확인 불가 정보는 '확인 필요' + 전화·공식 페이지 링크.
5. **위치정보는 세션 단위.** 서버에 저장하지 않는다.
6. **탄소·친환경 주장은 하지 않는다.** 이번 MVP 범위가 아니다.

화면은 **서버 렌더링 + GET 폼/링크**로만 동작합니다. 상태가 전부 쿼리스트링에 있어서
무대에서 JS 가 죽어도 스와이프 대신 링크로 동작하고, 바텀시트도 쿼리로 여닫습니다.

## 알려진 한계

- 후보 범위가 **성산·우도권**입니다 (스냅샷 반경 15km). 제주 전역은 `scripts/snapshot.py` 의
  `tour-jeju` 로 확장 가능 (관광공사 개발계정 1,000건/일).
- 위치 감지·검색이 둘 다 없으면 **성산항을 현재 위치로 간주**합니다 (시연 임시 고정).
- 기상특보 API 는 승인 대기(403)라 판정에 안 들어가며, 화면에 그렇게 표시됩니다.
- 브라우저 실기기에서의 스와이프 제스처·위치 권한 팝업은 수동 확인이 필요합니다.
